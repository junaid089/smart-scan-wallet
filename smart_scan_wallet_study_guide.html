Core Concepts & Terminology

Building blocks you need to understand full-stack AI applications

Before diving into code, let's establish a clear understanding of the fundamental concepts used in modern AI-powered web applications.

💡 What is a Full-Stack AI SaaS? A SaaS (Software-as-a-Service) is an application hosted on the web that users can access on-demand. A Full-Stack AI SaaS combines a visual user interface (Frontend), a backend server (FastAPI), a database (PostgreSQL), and Artificial Intelligence APIs (OpenAI) to automate complex manual tasks.

🔌 REST API

A structured way for the frontend (browser) to talk to the backend (server) using HTTP requests (GET, POST).

⚡ Async (Asynchronous)

Allows the server to handle thousands of requests simultaneously without waiting idly for database or AI responses.

👁️ Vision OCR

Optical Character Recognition powered by Multimodal AI that reads text and numbers from raw images.

💬 RAG-Lite / Text-to-SQL

Converting plain user English into safe database queries (SQL) so users can chat directly with their financial records.

🔐 JWT (JSON Web Token)

A digital passport given to users after logging in, allowing them to access protected endpoints securely.

🗄️ ORM (SQLModel)

Object-Relational Mapping allows developers to interact with database tables using Python code instead of raw SQL strings.

High-Level Tech Stack & Restaurant Analogy

Understanding how every layer of the application works together

To understand how a full-stack project works, imagine a high-end restaurant:

🍽️ The Restaurant Analogy:
  • Frontend (Next.js 14): The Dining Room & Menu. It's what the customer sees and interacts with.
  • Backend Gateway (FastAPI): The Waitstaff & Manager. They take orders (HTTP requests), check authorization, and coordinate between kitchen and pantry.
  • Database (PostgreSQL & SQLModel): The Pantry & Refrigerator. Safely holds organized raw ingredients (user accounts, expense rows).
  • AI Engine (OpenAI GPT-4o-mini): The Master Chef. Reads messy paper recipes (receipt images) and turns them into organized dishes (JSON data).
  • Storage (Supabase Storage): The Filing Cabinet. Stores original receipt photos safely in the cloud.
💡
Key Advantage of Async Architecture: In traditional servers, if 100 users upload receipts at the same time, the server blocks and waits for each receipt. In Smart-Scan Wallet's asyncpg + FastAPI setup, the server delegates AI calls asynchronously, remaining 100% responsive!

Deep Dive: Vision OCR Engine

How raw images turn into structured database records

Receipt OCR in Smart-Scan Wallet does not use traditional keyword matching. Instead, it uses Multimodal Large Language Models (LLMs) with strict system prompt enforcement.

The 5-Step OCR Pipeline

  1. Image Ingestion: The user selects a JPEG/PNG/HEIC image file.
  2. Storage Upload: StorageService assigns a unique UUID name (`user_id/timestamp_uuid_name.jpg`) and uploads it to Supabase (or local storage).
  3. Vision Prompting: The receipt URL (or base64 payload) is sent to gpt-4o-mini with strict instructions to return only JSON.
  4. Validation & Parsing: Python cleans markdown formatting (` ```json `), parses the JSON, normalizes the date, validates the amount Decimal, and maps the category to a strict Enum.
  5. DB Persistence: An Expense record is created and saved to PostgreSQL.
⚠️
Category Enforcement: AI output can be unpredictable. If GPT outputs "Groceries", the system's normalization logic maps it to the strict Enum value "Food". If unmapped, it gracefully defaults to "Other".

Security & Row-Level Data Isolation

How to keep financial data secure and private

Personal financial apps require enterprise-grade security. Here are the core defensive mechanisms implemented in this codebase:

🔒 Password Hashing

Passwords are never stored in plain text. They are hashed using bcrypt with automated salt generation.

🛡️ User Data Isolation

Every SQL query automatically filters by WHERE user_id = current_user.id, preventing User A from seeing User B's expenses.

🛑 SQL Injection Defense

The AI Chat Service validates all generated SQL queries. Any query containing keywords like DROP, DELETE, or UPDATE is immediately rejected.

2. Text-to-SQL Security Guard (app/services/chat_service.py)

This function verifies that AI-generated queries cannot alter or damage the database:

def validate_sql_query(sql: str) -> bool:
    normalized = " ".join(sql.upper().split())
    
    # Prohibited dangerous SQL operations
    dangerous_keywords = [
        "INSERT", "UPDATE", "DELETE", "DROP", "TRUNCATE",
        "ALTER", "CREATE", "GRANT", "EXEC", "--"
    ]
    
    for keyword in dangerous_keywords:
        if keyword in normalized:
            return False
            
    # Must begin with SELECT statement
    return normalized.startswith("SELECT")

Self-Assessment Quiz & Practice Exercises

Test your knowledge on full-stack AI development

Q1: Why does Smart-Scan Wallet use AsyncPG instead of synchronous database drivers?
Click to reveal answer
Answer: AsyncPG allows the server to handle concurrent operations (like waiting for OpenAI Vision API responses) without blocking the thread looper. This ensures high throughput and responsiveness.
Q2: How does the system prevent User A from seeing User B's expenses in the Chat interface?
Click to reveal answer
Answer: The Chat service dynamically injects `WHERE user_id = {user_id}` into the system prompt and programmatically validates that the generated SQL query enforces this filter before executing against PostgreSQL.
Q3: What happens if Supabase storage is unconfigured or offline during a receipt upload?
Click to reveal answer
Answer: The `StorageService` degrades gracefully to local disk storage (`/app/uploads`), ensuring receipt image processing and OCR continue without throwing a 500 fatal error.
Q4: What are the two core responsibilities of OpenAI GPT-4o-mini in this project?
Click to reveal answer
Answer: 1) Multimodal Vision OCR (extracting structured merchant, date, amount, and category from receipt photos), and 2) Text-to-SQL query generation and human answer synthesis for financial queries.
